# 獨立編修版的匯入與驗證方式

本次版號為 `2026-10-10`。實際完成日期與檢查結果記錄於本次交付資料夾；版號不因工作跨日而改名。

## 來源與版本

唯一主要來源是指定的154頁 Anthropic PDF。來源比較依 PDF 檔案頁序，由1起算；文字擷取僅供檢索，重要數字與圖表需另記實際開圖頁序。模型審稿者分開上下文，並不構成對事件底層紀錄的外部獨立驗證。

完成的複核版存於 `content-editions/2026-10-10/`；編輯工作檔與兩階段紀錄位於工作區的 `editorial-audit/independent-copyedit-2026-10-10/`。網站 repository 的封存稿讓 CI 不必依賴工作區外的私人路徑。PDF 不會打包進網站。

`scripts/edition-config.json` 指定唯一可匯入的當前版本。匯入器驗證全文 SHA-256、標題、案例 ID、頁碼與修訂日期，再建立網站副本。預設僅核對，加 `--write` 才寫入；`--check` 比對所有網站副本及衍生紀錄。舊版 finalizer 已停用，避免重新改寫10月9日原稿。

## 為何取消固定粗體與區塊數量

舊設定要求每篇恰好兩段粗體、全部恰好32篇台灣延伸。這些數量是呈現決定，不能替代來源忠實度。新版由實際複核稿決定粗體與編者區塊，逐篇記錄選句、數量與正文雜湊，再核對所有選句確實呈現、編者區塊數量一致且有明確標示。

來源忠實度檢查保留並加強：全文、標題、摘要、日期、來源頁碼、案例 URL、主／補充案例關係及共用來源關係均有比對。呈現層只包裝已審定段落，不再刪除「以下是編者…」等原稿歸因。額外比對 HTML 中的原稿段落，防止正文正確但呈現時遺失文字。

## 本機與 GitHub CI

`npm run verify:content` 檢查封存版、網站副本、呈現設定、來源頁序、44篇審查覆蓋紀錄及編輯完整性測試。在原工作區執行時，另外驗證原始材料與工作區稿件；在 CI 無原始材料時，明示只核對 repository 封存稿，不能聲稱重讀了 PDF。

`npm run build` 接著執行 Astro check、靜態建置和輸出檢查。CI 分別以根路徑與 `/ai-threat-watch/` 子路徑執行，核對68頁及內部連結／資源。

瀏覽器與手機大字檢查是介面驗證，不能稱為台灣一般讀者的實際閱讀測試。2026-10-14依使用者新增授權，將驗證後的靜態網站部署至 Sites，預設僅擁有者可登入查看。
